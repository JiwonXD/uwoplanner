# 월드 데이터 수집

`scripts/collect_world.py`는 Python 3.10 이상 표준 라이브러리만 사용한다.
공식 맵·대항오헬퍼·도우미·나침반의 **원문 스냅샷과 추출 가능한 데이터**를 저장한다.
현재 배치 도구의 항해사 DB나 배포 파일을 변경하지 않는다. 수집 결과를 게임의 최신
정답으로 확정하지 않으며, 계산식 전체를 실행 가능한 게임 엔진으로 옮기는 작업은 포함하지 않는다.

## 실행

```powershell
# 기본: 전체 목록 페이지, 캐시 재사용, 요청 간격 1초
npm run collect:world

# 공식/도우미만 먼저 확인
npm run collect:world -- --sources official tips

# 실제 원격 갱신 (캐시가 있으면 기본 실행은 다운로드하지 않는다)
npm run collect:world -- --refresh

# 저장된 스냅샷만 재처리. 네트워크 요청 없음
npm run collect:world -- --offline

# 항해사 개별 상세와 공식 도시/교역품 검색 상세도 요청
# 수백 페이지이므로 수십 분 걸릴 수 있다. 차단된 공식 상세는 첫 실패에서 중단한다.
npm run collect:world -- --details

# 첫 목록 페이지만 보는 불완전한 점검 실행
npm run collect:world -- --quick --output data/world-quick

npm run test:collector
```

종료 코드 0은 요청한 수집 과정에서 보고된 오류가 없다는 뜻이다. 전체 요구사항의
정규화 완료를 뜻하지 않는다. 2는 일부 차단·누락·미지원 파서가 있으나 결과 저장은
완료됐다는 뜻이며 `report.json`을 확인한다. 예상 밖 프로그램 오류는 1이다.
현재 나침반 동선 파서 및 금지된 헬퍼 API 때문에 전체 실행은 정상적으로 2를 반환한다.
오프라인에서도 원래 수집하지 못한 URL은 누락으로 표시한다.

## 결과

`data/site-source/world/`에는 URL/POST 검색 조건별 메타데이터와 내용 SHA-256별
원문이 저장된다. `data/world/`에는 다음 결과가 생성된다. 두 디렉터리는 Git에서 제외한다.
다른 출력 경로를 지정했다면 그 경로의 커밋 여부는 별도로 확인한다.

| 파일 | 내용 |
| --- | --- |
| `official.json` | `dbMap` 좌표와 `searchList` 검색 목록. 선택한 경우 상세 HTML 표 |
| `tips.json` | `datasets.UWO`, 교역 항구, 생산, 연대기, 작위, 종업원, 육탐 등 21개 JSON 테이블 |
| `helper.json` | 페이지별 품목 레코드, HTML 표, 스킬/선박 카드 원문, 장비/부품 수치표 |
| `compass.json` | 페이지 및 공개 정적 JS 파일 목록. 스크립트 내용은 원문 캐시에서 참조 |
| `cities.json` | 공식 도시 + 도우미 도시/교역품 보완, 필드별 출처, 충돌 후보 |
| `manifest.json` | 이번 처리에서 사용한 URL, 요청 조건, 수집 시각, 해시, 원문 파일명, HTTP 갱신 정보 |
| `report.json` | 성공·부분 성공·실패, 추출 개수, 상세 모드 여부, 누락과 외부 관측 필요 항목 |

`helper.json`의 `pages[].records[]`는 `kind`, 사이트 내부 `id`, `name`, 원문 `fields`를
가진다. 페이지별 중복 레코드는 유지하며 보고서 개수는 `(kind,id)` 기준이다.
스킬 레벨 표는 `pages[].blocks[]`에서 해당 카드와 함께 보존한다. 표의 각 행이나
문자열을 이미 정규화한 수치라고 해석하지 않는다. 기여 버튼의 빈 필드는 실제 카드
표시와 다를 수 있으므로 `blocks`와 원문도 확인한다.

## 요청 항목별 수집 범위

| 항목 | 실제 추출/보존 방식 | 남은 작업 |
| --- | --- | --- |
| 도시·마을·발견물 좌표 | 공식 `dbMap`; 도우미 `UWO.cities`, `VILLAGE_INFO`, `LAND`, `CONSTEL` | 좌표계별 변환·동일 장소 검토 |
| 신규 도시 | 도우미 도시에 쾰른·스트라스부르 포함. 공식 도시와 합집합 | 헬퍼 지도 API는 robots 금지 |
| 도시 지역·교역품·명산품·계절·해금 | 도우미 `PORTS[].items`, `UWO.items/categories/seasonTables`; 공식 `searchList` | 공식 상세는 `--details`, 접근 거부 가능 |
| 시설·건조 가능 항구 | 헬퍼 선박 `port_text`, 도우미 `SHIPS` | 도시 시설 API 수집 금지; 별도 허용된 출처 필요 |
| 대유행 권역·이벤트·게임 월 | 도우미 `UWO.regions/calendar/pandemic`; 계산 코드 원문 | 수식 이식 및 게임과의 검증 |
| 기타 지도 레이어·동선·주의사항 | 도우미 HTML과 나침반 정적 JS 원문, `STAFF`, `LAND`, `CONSTEL` | 함수/JS 객체로 작성된 동선 파서 미구현 |
| 물교 품목·수량·상태·보정 | 도우미 `VILLAGE_INFO`, `VSHEET`, `VSAMP`; 헬퍼 계산 페이지 원문 | 헬퍼 물교 API 금지. 원문 계산식/비JSON 상수 정규화 필요 |
| 생산 | 도우미 `PROD`; 헬퍼 production 레코드와 페이지 | 레시피 간 통합 ID, 수치 검증 |
| 항해사 국가·언어·고용 | 헬퍼 전체 목록 표; `--details`로 연결된 개별 상세 표 | 기본 실행은 개별 상세를 다운로드하지 않음 |
| 판매 증가 제독 | 도우미 `ADMIRAL` | 게임 최신 스킬과 대조 |
| 선박·장비·부품·스킬 | 헬퍼 전체 목록/카드/레벨 표, `EQ_DATA`, `PART_DATA`; 도우미 `SHIPS` | 타입 정규화 및 기존 배치 DB 연결 |
| 연대기·작위·면세 | 도우미 `CHRONICLES`, `TITLES` | 이동 문장 내 구매/전투를 별도 이벤트로 분리하려면 추가 파서 필요 |
| 투자 계산 | 헬퍼 investment 페이지 원문 | 수식 포팅·검증 |
| 판매 수량·부양 일정/상승률·바닷길 거리 | `report.external_requirements` | 게임 화면/도움말/제보/해안선 기반 별도 수집·계산 |

도우미의 `UWO.schedule`에 저장된 특정 날짜 일정은 최신 실시간 일정으로 취급하면 안 된다.
요청의 222/68/637/1,287/378/1,395 등은 참고 개수이며 파서의 고정 조건으로 쓰지 않는다.
갱신으로 개수가 달라지면 보고서와 원문을 비교한다.

## 출처 선택과 안전한 재처리

2026-10-17 실행 및 오프라인 재처리에서 확인한 결과:

- 공식 좌표: 도시 222, 마을 68, 발견물 1,287. 교역품 검색 목록 637.
- 공식+도우미 통합 도시 224: 쾰른·스트라스부르 추가. 별칭은 명시된 매핑으로 합쳤다.
- 헬퍼 항해사 목록 22페이지/635행, 스킬 24페이지/1,395개, 선박 378개.
- 도우미 연대기 32명, 작위 국가 7개. `UWO.regions`는 18개여서 요청의 권역 20개와
  다르다. 누락된 두 권역을 추측해서 만들지 않았다.
- 나침반 정적 JS까지 원문 보존. 동선의 구조화는 아직 미지원이다.

- `cities.json`은 공식 지리 좌표와 식별자를 보존하고, 도우미의 신규 도시·기후·교역품을
  보완한다. 이름은 정확 일치와 도우미가 명시한 `PORT_ALIAS`/`PORT_RENAME`만 사용한다. 추측성 유사 이름
  병합을 하지 않는다. `community_only`에는 새 도시뿐 아니라 미해결 별칭도 있을 수 있다.
- 공식 `latitude/longitude`, 도우미 `tips_map_percent_xy`는 다른 좌표계다. 누락된 위경도를
  이미지 좌표로 채우지 않는다. 사이트별 ID도 서로 같은 ID라고 가정하지 않는다.
- 출처 우선순위는 최신성 검증과 다르다. `fetched_at`, `Last-Modified`, 파일명 버전만으로
  게임 정보가 최신이라고 확정하지 않는다. 충돌은 원값·선택값·출처를 함께 보존한다.
- 공개 원문을 로컬에서 해석하며 원격 JS의 `eval`, 브라우저 실행, 함수 호출을 하지 않는다.
  JSON 할당식만 엄격하게 읽고 JS 표현식은 거부한다. 파서 변경 후 `--offline`으로 재현한다.
- 각 사이트 robots.txt의 가장 구체적인 규칙을 적용한다. 헬퍼 `/api/`는 수집하지 않는다.
  403/429 등은 우회하거나 반복 재시도하지 않는다. 로그인·기여·관리 페이지를 호출하지 않는다.
- 아이콘 URL/식별자가 데이터에 있어도 이미지 자체를 다운로드하거나 서비스에 재배포하지
  않는다. 이미지 권리 확인은 별도다. 수집 파일은 현재 빌드에 포함되지 않는다.
