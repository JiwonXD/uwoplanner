# 항해사 DB 초안

공개 시뮬레이터에서 추가 추출한 640명 데이터와 효과 수치표는
[simulator/README.md](simulator/README.md)에 정리했다. 아래 파일은 엑셀 기준 스냅샷으로 보존한다.

제공된 아스트라이오스 v260708 엑셀의 `항해사` 시트에서 추출한 스냅샷이다.
원본 파일은 수정하지 않았다. 게임의 최신 상태 및 원본 스탯의 성장 기준은 검증하지 않았다.

## 결과

- `navigators.sqlite`: 정규화된 SQLite DB 및 원본 셀 기록.
- `navigators.json`: 웹에서 읽을 수 있는 동일 항해사·스탯·효과·기술 데이터.
- `import-report.json`: 추출 개수와 확인이 필요한 항목.

634명, 스탯 7,608개, 효과 이름 496종, 기술 이름 107종을 추출했다.
항해사별 효과 연결은 6,401개, 기술 연결은 1,314개다.
효과·기술의 수는 말미의 `LV2` 등을 분리한 이름 기준이며 유사 이름을 임의로 합치지 않았다.

## 구조

| 테이블 | 내용 |
| --- | --- |
| source | 원본 파일 이름, SHA-256, 버전 표기, 추출 기준 |
| navigator | 내부 ID, 이름, 등급, 타입, 직업, 원본 행 |
| navigator_stat | 항해사별 12종 수치와 성장 기준(현재 NULL) |
| ability | 효과·기술 이름, 구분, 분류 근거, 적용 범위와 중첩 규칙 |
| navigator_ability | 항해사별 보유 효과·기술, 습득 레벨, 획득 경로, 원문과 원본 셀 |
| source_cell | 12개 시트의 값 및 수식 원문. 수식을 실행하지 않음 |

내부 ID는 이름 기반 해시이며 게임 공식 ID가 아니다. 이름이 수정되면 ID 이관이 필요하다.
같은 항해사가 여러 칸에 같은 효과를 가지더라도 원본 칸별로 별도 보존한다.
NULL은 미확인이며 0이나 효과 없음으로 해석하면 안 된다.

## 스탯과 활성 효과

포격술·충파술·지원술·백병술, 박물학·심미학·척후법·보급법,
구매 전략·판매 전략·협상 전략·교환 전략을 숫자로 저장했다.
순위표의 보정값이나 작성자 점수는 항해사 스탯에 섞지 않았다.
저장된 스탯을 특정 레벨의 기본 스탯 또는 사용자 실측 스탯으로 확정하지 않았다.

10/30/50/70레벨 효과, 잠재 효과, 인연 연대기 효과 및 1/50레벨 기술을 구별한다.
보유 데이터는 현재 활성화된 효과를 의미하지 않는다. 배치툴에서는 사용자별 보유 여부,
성장 상태, 잠재 효과 해금, 인연 완료, 장비 및 스탯 보정을 별도 데이터로 관리해야 한다.
명시된 `LV2` 등은 `explicit_level`로 저장했으며 실제 중첩량인
`stack_contribution`은 아직 NULL이다. 표기가 없는 효과도 임의로 1로 채우지 않았다.

## 배치 계산 전 확인할 규칙

1. 496종 효과 중 182종은 효과별 목록에서 분류 근거를 찾았고, 나머지 314종은 분류가 비어 있다.
2. 해전 기술은 사용자 설명에 따라 선박 범위를 기록했다. 효과는 개별 적용 범위를 확인해야 한다.
   사용자 설명은 모험·교역=선단, 전투=선박이지만 `모험(효과)!L3`에는 노 젓기가
   갤리류 선박에서 선박별 합산된다고 기재돼 있다. 이 차이는 자동으로 확정하지 않았다.
3. 효과별 중첩 공식·상한·선박 조건과 기술의 합산 방식을 확인해야 한다.
4. 원본 스탯의 레벨·성장·장비 기준과 실제 선박/선단 반영 공식을 확인해야 한다.
5. 전용 장비와 직업 고유 효과 등 보조 시트에만 있는 정보는 `source_cell`에 보존했으며
   항해사의 기본 활성 효과로 자동 합산하지 않았다.

이 초안으로 항해사 검색·상세 조회와 보유 항해사 선택을 만들 수 있다.
정확한 최적 배치 계산에는 위 규칙과 사용자별 성장 상태가 추가로 필요하다.

## 갱신

Python과 읽기용 openpyxl로 프로젝트 루트에서 실행한다.

```powershell
python scripts/import_navigators.py '원본.xlsx' --output data
```

동일한 형식의 새 파일을 입력하면 생성된 DB와 JSON이 갱신된다. 직접 수정한 규칙을
생성 파일에 저장하지 말고 별도 규칙 테이블/파일에서 관리해야 한다.
원본의 외부 구글 시트 수식을 재계산하거나 링크를 새로 가져오지 않는다.
파일에 저장된 값과 출처를 보존하며 SHA-256으로 스냅샷을 구별한다.

검증: 이름 중복, 스탯 누락/숫자 형식, SQLite 무결성 및 외래 키,
항해사별 스탯·효과·기술 원본 대조와 출력 개수 일치를 확인했다.
